# Capability Ownership and Responsibility Matrix

Every PEWA allocation below is a **candidate responsibility boundary** for Founder and Miledge review, not a Miledge architecture disposition. F01 approves the PEWA product thesis and business responsibilities; it does not decide final canonical data authority or state ownership. “Potential shared relationship” means investigate reuse; it does not assert service existence.

## Boundary tests for later disposition

- Keep business content and fulfilment responsibility distinct from PEWA platform duties (PEWA F01 §7).
- Keep PEWA domain meanings distinct from channel/provider transport (F01 §8; MV-207 §4).
- Validate existing Miledge Domains and Shared Platforms before proposing any new layer (MPA-002 §8; MPA-005 §§3.2, 7).
- Use actual owner, current status, interface/contract, operating evidence and consumer readiness before calling a shared capability reusable or available.
